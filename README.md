# Holliday Planner

დასვენების პერსონალური და ჯგუფური დაგეგმვის ვებაპლიკაცია.

## საჯარო ვერსია

განთავსების მისამართია https://holliday-planner.dynamicabode1.chatgpt.site.

ვებინტერფეისი განთავსდება Sites-ის საჯარო ჰოსტინგზე, ანგარიშები იმუშავებს Supabase Auth-ით. საიტის ნახვა ხელმისაწვდომია ბმულის მქონე ნებისმიერი ადამიანისთვის. რეგისტრაციის წერილებისთვის მოქმედებს Supabase-ის საფოსტო სერვისის პირობები.

ჰოსტინგის კონფიგურაცია ინახება `.openai/hosting.json` ფაილში. Vite-ის build იღებს საჯარო Supabase კონფიგურაციას ადგილობრივი `.env.local` ფაილიდან. შემდგომ განთავსებამდე თავიდან უნდა აიგოს პროექტი შესაბამისი გარემოს მნიშვნელობებით.

მომხმარებელი უთითებს ინტერესებს, დანიშნულების ადგილს, თარიღებს, ბიუჯეტსა და თანამგზავრებს. აპლიკაცია აგროვებს ამინდისა და დანიშნულების მონაცემებს, ამზადებს AI რეკომენდაციას, ადარებს ალტერნატივებს და მომხმარებლის დადასტურების შემდეგ აგზავნის მოწვევებს.

## მიმდინარე ეტაპი

2026-11-11 — დამატებულია რეგისტრაციის, შესვლისა და პაროლის აღდგენის ფორმები, ინტერესების არჩევა/რედაქტირება და Supabase Auth-ის ინტეგრაცია. ამ სამუშაო კომპიუტერში Supabase-ის კავშირი შემოწმებულია. რეალური ანგარიშის სცენარისთვის დარჩენილია დაბრუნების მისამართების გამართვა და მომხმარებლის ელფოსტის დადასტურება. გეგმების შენახვა და ამინდი შემდეგი ეტაპების სამუშაოა.

პროექტის სახელწერა შენარჩუნებულია მომხმარებლის არჩევანით — **Holliday Planner**.

მიმდინარე სამუშაო ფარგლებია სამი ძირითადი დადასტურება: დამოუკიდებელი დაგეგმვა, ვებგვერდის განხორციელება და ანგარიშგება. AI-ის პრაქტიკული გამოყენების ცალკე დავალებები და AI ინტეგრაცია ამ ეტაპზე გადადებულია; წინა გეგმებში აღწერილი AI შესაძლებლობები სამომავლო იდეებად რჩება.

## გაშვება

რეკომენდებულია Node.js 24 LTS, მინიმუმ 24.15.0 (შემოწმებულია 24.22.0-ზე), და npm. ასევე მხარდაჭერილია Node.js 22.22.2+ (22.x) ან 26+. ქვედა ზღვარი ითვალისწინებს ნავიგაციის ტესტებისთვის საჭირო JSDOM-საც. ბრძანებები გაუშვი `holliday-planner` საქაღალდეში:

```powershell
npm.cmd ci
npm.cmd run dev
```

გახსენი ტერმინალში ნაჩვენები ლოკალური მისამართი, ჩვეულებრივ `http://localhost:5173`. Windows PowerShell-ზე `npm.cmd` მუშაობს მაშინაც, როცა `npm.ps1` execution policy-ით შეზღუდულია. სხვა ტერმინალებში შეგიძლია გამოიყენო `npm`.

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
```

`build` ჯერ TypeScript-ს ამოწმებს და შემდეგ ოპტიმიზებულ შედეგს `dist/`-ში ქმნის. `preview` ამ შედეგს ლოკალურად აჩვენებს, ჩვეულებრივ `http://localhost:4173`. სერვერის გასაჩერებლად გამოიყენე `Ctrl+C`.

მთავარი გვერდი და ფორმების ვალიდაცია მუშაობს გარე ანგარიშის გარეშეც. რეგისტრაციისა და შესვლის გასააქტიურებლად შეავსე `.env.local` საჯარო Supabase URL-ითა და Publishable key-ით. შაბლონია `.env.example`. დეტალური ნაბიჯები მოცემულია [დაკავშირების ინსტრუქციაში](docs/04-supabase-setup.ka.md). შრიფტი და SVG ილუსტრაციები ლოკალურად იტვირთება.

## ეტაპის შემოწმება

ავტომატური ტესტები ამოწმებს ნავიგაციას, ფორმების ვალიდაციას, ინტერესებს, სესიის აღდგენას, შესვლას/გასვლას, პაროლის აღდგენასა და განმეორებითი გაგზავნის დაცვას. ანგარიშების ტესტები იყენებს სატესტო Auth კლიენტს.

ბრაუზერში შემოწმებულია 320, 390, 768 და 1440 პიქსელის სიგანეები, მობილური ნავიგაცია და ფორმების ვალიდაცია. გვერდებისა და VS Code-ში გახსნილი კოდის სქრინშოთები ინახება [მტკიცებულებების საქაღალდეში](evidence/README.ka.md). Supabase-ის Auth პარამეტრების რეალური მოთხოვნა წარმატებულია. ანგარიშის, წერილისა და სესიის სრული სცენარი დასასრულებელია დაბრუნების მისამართების გამართვის შემდეგ.

ტექნიკური საფუძვლის ოფიციალური წყაროები: [Vite](https://vite.dev/guide/) და [Tailwind-ის Vite ინტეგრაცია](https://tailwindcss.com/docs/installation/using-vite).
