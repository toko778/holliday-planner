# Holliday Planner

დასვენების პერსონალური და ჯგუფური დაგეგმვის ვებაპლიკაცია.

მომხმარებელი უთითებს ინტერესებს, დანიშნულების ადგილს, თარიღებს, ბიუჯეტსა და თანამგზავრებს. აპლიკაცია აგროვებს ამინდისა და დანიშნულების მონაცემებს, ამზადებს AI რეკომენდაციას, ადარებს ალტერნატივებს და მომხმარებლის დადასტურების შემდეგ აგზავნის მოწვევებს.

## მიმდინარე ეტაპი

2026-11-10 — დადასტურება 2-ის ტექნიკური საფუძველი: React + TypeScript + Vite + Tailwind CSS, ქართული მთავარი გვერდი, ჩამოსაშლელი გზამკვლევი და ადაპტირებადი ნავიგაცია. ანგარიშები, გეგმების შენახვა და API-ები შემდეგი ეტაპების სამუშაოა.

პროექტის სახელწერა შენარჩუნებულია მომხმარებლის არჩევანით — **Holliday Planner**.

მიმდინარე სამუშაო ფარგლებია სამი ძირითადი დადასტურება: დამოუკიდებელი დაგეგმვა, ვებგვერდის განხორციელება და ანგარიშგება. AI-ის პრაქტიკული გამოყენების ცალკე დავალებები და AI ინტეგრაცია ამ ეტაპზე გადადებულია; წინა გეგმებში აღწერილი AI შესაძლებლობები სამომავლო იდეებად რჩება.

## გაშვება

რეკომენდებულია Node.js 24 LTS, მინიმუმ 24.15.0 (შემოწმებულია 24.22.0-ზე), და npm. ასევე მხარდაჭერილია Node.js 22.22.2+ (22.x) ან 26+. ქვედა ზღვარი ითვალისწინებს ნავიგაციის ტესტებისთვის საჭირო JSDOM-საც. ბრძანებები გაუშვი `holliday-planner` საქაღალდეში:

```powershell
npm.cmd ci
npm.cmd run dev
```

გახსენი ტერმინალში ნაჩვენები ლოკალური მისამართი, ჩვეულებრივ `http://localhost:5173`. Windows PowerShell-ზე `npm.cmd` მუშაობს მაშინაც, როცა `npm.ps1` execution policy-ით შეზღუდულია. სხვა ტერმინალებში შეგიძლია გამოიყენო `npm`.

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
```

`build` ჯერ TypeScript-ს ამოწმებს და შემდეგ ოპტიმიზებულ შედეგს `dist/`-ში ქმნის. `preview` ამ შედეგს ლოკალურად აჩვენებს, ჩვეულებრივ `http://localhost:4173`. სერვერის გასაჩერებლად გამოიყენე `Ctrl+C`.

მიმდინარე გვერდს არ სჭირდება `.env`, გარე ანგარიში ან API გასაღები. შრიფტი და SVG ილუსტრაციები ლოკალურად იტვირთება.

## ფაილების სტრუქტურა

```text
src/

  components/Landscape.tsx   # საკუთარი SVG ილუსტრაციები
  data/destinations.ts       # მიმართულებების საინფორმაციო ტექსტები

  styles.css                # Tailwind, დიზაინი და ეკრანის ზომები
tests/navigation.test.mjs    # ნავიგაციისა და ბმულების 6 შემოწმება
docs/                       # შენარჩუნებული დაგეგმვის დოკუმენტები
evidence/                   # შემოწმების ჟურნალი და მტკიცებულებების სტატუსი
```

## ეტაპის შემოწმება

ავტომატური ტესტები ამოწმებს მობილური მენიუსა და dropdown-ის მდგომარეობებს, Escape-ს, ფოკუსის დაბრუნებას, გარეთ დაწკაპუნებას, ეკრანის ზომის ცვლილებისას მენიუს განულებასა და შიდა ბმულების სამიზნეებს. JSDOM არ ამოწმებს ვიზუალურ განლაგებას.

ბრაუზერის ვიზუალური შემოწმება და კოდის/გვერდის სქრინშოთები დარჩენილია: Computer Use-მა Chrome-ის მიმდინარე URL საიმედოდ ვერ დაადგინა და UI-წვდომა ამ სვლისთვის შეწყვიტა. სრული სტატუსი და გადასაღები კადრები აღწერილია [მტკიცებულებების ჩანაწერში](evidence/README.ka.md).
