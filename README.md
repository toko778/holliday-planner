# Holliday Planner

დასვენების პერსონალური და ჯგუფური დაგეგმვის ვებაპლიკაცია.

## საჯარო ვერსია

განთავსების მისამართია https://holliday-planner.dynamicabode1.chatgpt.site.

საიტი განთავსებულია Sites-ის საჯარო ჰოსტინგზე. Supabase Auth მართავს ანგარიშებს, Cloudflare Worker — დაცულ API-ს, D1 — მომხმარებლის გეგმებს, Groq — ქართულ AI რეკომენდაციებს, Open-Meteo — ხელმისაწვდომ ამინდის პროგნოზს. საიტის ნახვა საჯაროა; პირადი გეგმების შენახვა და AI გენერაცია მოითხოვს შესვლას.

ჰოსტინგის კონფიგურაცია ინახება `.openai/hosting.json` ფაილში. Vite-ის build იღებს საჯარო Supabase კონფიგურაციას ადგილობრივი `.env.local` ფაილიდან. Groq-ის საიდუმლო გასაღები ინახება ჰოსტინგის სერვერულ გარემოში და ბრაუზერის build-ში არ ხვდება. განთავსება იყენებს `dist/server/index.js` Worker-ს და D1 მიგრაციებს.

მომხმარებელი უთითებს მიმართულებას, ინტერესებს, თარიღებს, გამგზავრების ადგილს, ტრანსპორტს, ადამიანების რაოდენობასა და ბიუჯეტს. აპლიკაცია ინახავს მონახაზს, იღებს ხელმისაწვდომ ამინდს და ამზადებს ქართულ AI დღის გეგმას. შედეგს აქვს რჩევები, თან წასაღები ნივთები, ალტერნატივები და ჩამოტვირთვის შესაძლებლობა. ჯავშნები და მოწვევების გაგზავნა ამ ვერსიაში არ სრულდება.

## მიმდინარე ეტაპი

2026-11-11 — დამატებულია მოქმედი დაგეგმვა: ფორმა, მონახაზების შენახვა/რედაქტირება/წაშლა, სტატუსები, Groq AI და Open-Meteo. რეალურ შესულ ანგარიშში გამოჩნდა შექმნილი AI გეგმა და ბაზაში მისი შენახვაც დადასტურდა (`evidence/P2.9-ai-signed-in.json`). საჯარო საიტზე ამინდი იმ ცდისას მიუწვდომელი იყო და ეს შედეგში აშკარად გამოჩნდა. ანგარიშების ავტომატური სცენარები ცალკე იყენებს სატესტო Auth კლიენტს; რეალური Groq და ამინდის სერვისული მოთხოვნის შედეგი ინახება `evidence/P2.9-groq-live.json`-ში.

პროექტის სახელწერა შენარჩუნებულია მომხმარებლის არჩევანით — **Holliday Planner**.

მიმდინარე სამუშაო ფარგლებია სამი ძირითადი დადასტურება: დამოუკიდებელი დაგეგმვა, ვებგვერდის განხორციელება და ანგარიშგება. მომხმარებლის ახალი მოთხოვნით აპლიკაციაში AI ინტეგრაცია ჩართულია; რამდენიმე AI ინსტრუმენტის გამოყენების ცალკე საგამოცდო დავალებები ამ სამუშაოსგან დამოუკიდებელია. საბოლოო ანგარიში და 8-სლაიდიანი ქართული პრეზენტაცია მომზადებულია. [პრეზენტაცია](holliday-planner.ka.pptx) პროექტის მთავარ საქაღალდეშია, წარდგენის ტექსტი — `deliverables/`-ში, მხოლოდ სქრინშოტები — `Screenshots/`-ში, შემოწმების ჟურნალები — `evidence/`-ში.

## გაშვება

რეკომენდებულია Node.js 24 LTS, მინიმუმ 24.15.0 (შემოწმებულია 24.22.0-ზე), და npm. ასევე მხარდაჭერილია Node.js 22.22.2+ (22.x) ან 26+. ქვედა ზღვარი ითვალისწინებს ნავიგაციის ტესტებისთვის საჭირო JSDOM-საც. ბრძანებები გაუშვი `holliday-planner` საქაღალდეში:

```powershell
npm.cmd ci
npm.cmd run dev
```

გახსენი ტერმინალში ნაჩვენები ლოკალური მისამართი, ჩვეულებრივ `http://localhost:5173`. Windows PowerShell-ზე `npm.cmd` მუშაობს მაშინაც, როცა `npm.ps1` execution policy-ით შეზღუდულია. სხვა ტერმინალებში შეგიძლია გამოიყენო `npm`.

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run preview
```

`build` ამოწმებს TypeScript-ს, ამზადებს Vite კლიენტს `dist/client/`-ში და სერვერულ Worker-ს `dist/server/index.js`-ში. `preview` იმავე Worker-ს ლოკალურად აჩვენებს `http://127.0.0.1:4173` მისამართზე. `dev` და `preview` იყენებს ცალკე ლოკალურ SQLite ბაზას `runtime-data/planner.sqlite`-ში; გამოქვეყნებული საიტი — ჰოსტინგის D1 ბაზას. სერვერის გასაჩერებლად გამოიყენე `Ctrl+C`.

ლოკალური რეგისტრაციისთვის `.env.local`-ში შეავსე `VITE_SUPABASE_URL` და `VITE_SUPABASE_PUBLISHABLE_KEY`; AI-სთვის — სერვერული `GROQ_API_KEY` და `GROQ_MODEL=qwen/qwen3.8-27b`. შაბლონია `.env.example`. გასაღებს არ დაუმატო `VITE_` პრეფიქსი. ჰოსტინგზე სერვერული მნიშვნელობები Sites-ის გარემოს პარამეტრებში ინახება. საჯარო Supabase კონფიგურაციის აწყობა კვლავ Vite-ის გარემოს იყენებს. შრიფტი და SVG ილუსტრაციები ლოკალურად იტვირთება.

## ეტაპის შემოწმება

34 ავტომატური ტესტი ამოწმებს ნავიგაციას, ანგარიშებს, დაგეგმვას, ბიუჯეტის ერთეულებს, შენახვას, სხვა მფლობელისგან იზოლაციას, ძველი ვერსიის დაცვას, AI შეცდომებს, ლიმიტებსა და გასვლისას მონაცემების მოცილებას. ანგარიშებისა და AI შეცდომების ტესტები იყენებს სატესტო კლიენტებს; რეალური Groq/Open-Meteo მოთხოვნა ცალკე შემოწმებულია.

ბრაუზერში შემოწმებულია 320, 390, 768 და 1440 პიქსელის სიგანეები, მობილური ნავიგაცია, ფორმები და ბიუჯეტის ერთეულის ცვლილება. სქრინშოტები ინახება [Screenshots საქაღალდეში](Screenshots/), ჟურნალები და სრული სია — [evidence საქაღალდეში](evidence/README.ka.md). გეგმის გენერაცია მოითხოვს მოქმედ Supabase სესიას. რეალური მომხმარებლის სესიის სრული გამეორება ავტომატური ტესტის ნაწილად არ ითვლება.

ტექნიკური საფუძვლის ოფიციალური წყაროები: [Vite](https://vite.dev/guide/) და [Tailwind-ის Vite ინტეგრაცია](https://tailwindcss.com/docs/installation/using-vite).
