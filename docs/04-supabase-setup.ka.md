# Supabase-ის დაკავშირება

თარიღი — 2026-11-11.

აპლიკაციაში მზადაა რეგისტრაციის, შესვლის, გასვლის, ინტერესების შენახვისა და პაროლის აღდგენის კოდი. ამ ეტაპზე პროექტის URL და საჯარო Publishable key მოსაწოდებელია.

## 1. პროექტის შექმნა

1. გახსენი [Supabase Dashboard](https://supabase.com/dashboard) და შედი შენი ანგარიშით.
2. აირჩიე `New project` და უფასო გეგმის ორგანიზაცია.
3. სახელი მიუთითე `holliday-planner`, აირჩიე ახლომდებარე რეგიონი და ბაზის პაროლი შეინახე პირადად.
4. შექმნის დასრულების შემდეგ გახსენი `Connect` და მოძებნე `Project URL` და `Publishable key`.
5. კლიენტისთვის გამოიყენება `sb_publishable_` პრეფიქსიანი გასაღები. ბაზის პაროლი და Secret გასაღები რჩება კერძო კონფიგურაციაში.

ინტეგრაციის საფუძველია Supabase-ის React Auth გზამკვლევი. [ოფიციალური ინსტრუქცია](https://supabase.com/docs/guides/auth/quickstarts/react).

## 2. ადგილობრივი კონფიგურაცია

პროექტის ძირითად საქაღალდეში შექმენი `.env.local` და შეავსე ორი მნიშვნელობა.

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
```

შაბლონია `.env.example`. `.env.local` გამოირიცხება Git-იდან. Vite-ის `VITE_` ცვლადები ბრაუზერის კოდში გადადის, ამიტომ აქ გამოიყენება საჯარო გასაღები.

კონფიგურაციის დამატების შემდეგ თავიდან გაუშვი განვითარების სერვერი.

```powershell
npm.cmd run dev
```

როდესაც URL და გასაღები სწორად არის დამატებული, ანგარიშების განყოფილებაში მომზადების შეტყობინებას ჩაანაცვლებს ჩვეულებრივი ფორმა.

## 3. დაბრუნების მისამართები

Supabase-ში გახსენი `Authentication → URL Configuration`.

- `Site URL` მიუთითე `http://127.0.0.1:5173`.
- ლოკალური განვითარებისთვის `Redirect URLs` სიაში დაამატე `http://127.0.0.1:5173/**` და `http://localhost:5173/**`.
- განთავსებისას დაამატე რეალური საიტის ზუსტი მისამართი და შესაბამისად განაახლე `Site URL`.

აპლიკაცია დაბრუნებისთვის იყენებს მიმდინარე origin-ს, pathname-ს და `#account` განყოფილებას. PKCE ნაკადისთვის წერილის ბმული გახსენი იმავე ბრაუზერში და მოწყობილობაზე, საიდანაც დადასტურება მოითხოვე. [Redirect URL-ები](https://supabase.com/docs/guides/auth/redirect-urls) და [PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow).

## 4. ელფოსტის პირობები

დადასტურებისა და აღდგენის წერილებს გზავნის Supabase Auth. ჩაშენებული საფოსტო სერვისი სატესტო გამოყენებაზეა შეზღუდული და მიმღებები დაკავშირებულია პროექტის გუნდის მისამართებთან. სხვა მომხმარებლებისთვის საჭიროა საკუთარი SMTP სერვისის გამართვა. [ოფიციალური SMTP პირობები](https://supabase.com/docs/guides/auth/auth-smtp).

პირველი რეალური შემოწმებისთვის გამოიყენე საკუთარი ნებადართული სატესტო მისამართი. მიმღებების გაფართოებამდე გამართე დადასტურებული დომენი და შესაბამისი SMTP.

## 5. რეალური შემოწმება

1. შექმენი სატესტო ანგარიში შენი მისამართით და რამდენიმე ინტერესით.
2. იმავე ბრაუზერში გახსენი მიღებული დადასტურების ბმული.
3. შეამოწმე, რომ ანგარიშში ჩანს შენი სახელი და ინტერესები.
4. შეცვალე ინტერესები და შეინახე.
5. განაახლე გვერდი და გადაამოწმე სესიისა და ინტერესების აღდგენა.
6. გამოდი ანგარიშიდან და ხელახლა შედი ელფოსტითა და პაროლით.
7. საკუთარი ანგარიშისთვის მოითხოვე პაროლის აღდგენა და შეამოწმე ახალი პაროლით შესვლა.
8. `Authentication → Users` სიაში გადაამოწმე შექმნილი მომხმარებელი.
9. მოთხოვნის P2.6 ჩანაწერში მიუთითე გავლილი სცენარები და დარჩენილი შეზღუდვები.

სახელი და ინტერესები ინახება Auth მომხმარებლის metadata-ში და გამოიყენება პროფილის ინტერფეისისთვის. მომავალში მოგზაურობების ცხრილებს დაემატება მფლობელზე დაფუძნებული RLS წესები. წვდომის უფლებების გადაწყვეტილებებს განსაზღვრავს სერვერი და მონაცემთა ბაზის წესები.
