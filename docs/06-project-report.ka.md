## პროექტის მიზანი

Holliday Planner ეხმარება მომხმარებელს საქართველოში მოკლე დასვენების დაგეგმვაში. მომხმარებელი უთითებს მიმართულებას, თარიღებს, ადამიანების რაოდენობას, ბიუჯეტს, ტრანსპორტსა და ინტერესებს. საიტი ითვლის ჯგუფის ბიუჯეტს, ქმნის ქართულ AI დღის გეგმას და ინახავს მას პირად ანგარიშში.

საწყისი იდეის, მომხმარებლის სცენარების, სტრუქტურის, სამუშაო გეგმისა და შესრულების წესის აღწერა შენარჩუნებულია [პირველ დოკუმენტში](01-project-plan.ka.md). დაგეგმვის საწყისი commit-ია `b7959d4`.

## განხორციელებული ფუნქციები

- ქართული მთავარი გვერდი, სამი მიმართულების აღწერა, საკუთარი SVG ილუსტრაციები და ადგილობრივი ქართული შრიფტი.
- კომპიუტერის dropdown და ტელეფონის მენიუ, კლავიატურით მართვა და ფოკუსის დაბრუნება.
- Supabase რეგისტრაცია, შესვლა, გასვლა, სესიის აღდგენა და პაროლის აღდგენის ფორმა.
- მოგზაურობის ფორმა: ბაკურიანი, ყაზბეგი ან ბათუმი; გამგზავრების ადგილი; 1–7 დღე; 1–20 ადამიანი; ბიუჯეტი; ტრანსპორტი; ინტერესები და შენიშვნა.
- ბიუჯეტის ერთეული ერთი ადამიანისთვის ან მთელი ჯგუფისთვის. მაგალითად, 300 ₾ ადამიანზე და 2 მონაწილე იძლევა 600 ₾ საერთო ლიმიტს.
- მონახაზის შენახვა, გეგმების სია, გახსნა, რედაქტირება, სტატუსის ცვლილება, ფილტრი და საკუთარი გეგმის წაშლა დადასტურებით.
- Groq-ის რეალური ქართული AI პასუხი: დღის განრიგი, ბიუჯეტის რჩევა, თან წასაღები ნივთები, რჩევები და მიმართულების ალტერნატივები.
- ხელმისაწვდომი Open-Meteo პროგნოზი და აშკარა შეტყობინება მიუწვდომელ ან ნაწილობრივ დაფარულ თარიღებზე.
- შედეგის ტექსტურ ფაილად ჩამოტვირთვა. ალტერნატივის არჩევა ქმნის ახალ პირობებს და ახალ შეფასებას საჭიროებს.

## ტექნიკური გადაწყვეტა

ინტერფეისი აგებულია React, TypeScript, Vite და Tailwind ტექნოლოგიებით. Cloudflare Worker ასრულებს დაცულ API მოთხოვნებს. Supabase Auth მართავს ანგარიშებს, ხოლო D1 ინახავს გეგმებს და AI მოთხოვნების აღრიცხვას.

ბრაუზერი სერვერს გადასცემს მოქმედ სესიას. სერვერი გადაამოწმებს მას Supabase-ში და პირად SQL მოთხოვნებს მომხმარებლის გადამოწმებულ ID-ს უკავშირებს. სხვა მომხმარებლის გეგმა იმავე მისამართის ცოდნით ხელმისაწვდომი არ ხდება.

Groq-ის გასაღები ინახება მხოლოდ ჰოსტინგის სერვერულ გარემოში. AI იღებს მოგზაურობის პირობებს და არა ანგარიშის ელფოსტას. კლიენტის build, Git და მტკიცებულებები საიდუმლო გასაღებს არ შეიცავს.

AI მოთხოვნების გამეორება უნიკალური ID-ით იზღუდება. მოქმედებს მომხმარებლისა და საერთო დღიური ლიმიტები. მონაცემის ვერსია იცავს ახალი ცვლილების ძველი პასუხით გადაფარვისგან. სერვისის შეცდომისას მონახაზი რჩება შენახული.

დაწვრილებითი API, კონფიგურაცია და მონაცემთა მნიშვნელობა აღწერილია [ინტეგრაციის ინსტრუქციაში](05-ai-planner.ka.md).

ავტომატურ ტესტებში Auth-ისა და AI-ის პასუხები კონტროლირებადია. შენახვისა და იზოლაციის ტესტები იყენებს SQLite-ის ნამდვილ სქემას. რეალური გარე მოთხოვნა და რეალურ ანგარიშში ბრაუზერული ცდა ცალკე მტკიცებულებებია.

ავტორიზებულ ბრაუზერულ ცდაში გამოყენებულია გამოგონილი მოგზაურობის შენიშვნა. მტკიცებულებაში არ ქვეყნდება მომხმარებლის ელფოსტა, ID, კერძო გეგმა ან სესიის გასაღები. ბაზის მკითხველი გრძელ უჯრედებს ამოკლებს, ამიტომ მისგან სრული AI JSON-ის ხელახლა გაშიფვრა არ დადასტურებულა. სრული შედეგი ბრაუზერში ჩანდა.

ბრაუზერის ავტომატური მართვა URL-ის გადამოწმების შეზღუდვამ შეაჩერა საბოლოო განახლების ცდისა და AI შედეგის სქრინშოთის შენახვამდე. გვერდის განახლების შემდეგ იგივე გეგმის ხელახლა გახსნა ამ ცდის გავლილ ნაბიჯად არ აღირიცხება. სერვერულ ბაზაში შენახვა დამოუკიდებლად შემოწმდა.

## დარჩენილი შეზღუდვები

1. საჯარო საიტზე ავტორიზებული გენერაციისას ამინდის სერვისი მიუწვდომელი იყო. AI გეგმა შეიქმნა და ამინდის არქონა აშკარად გამოჩნდა. შემდგომ ვერსიაში გაუმჯობესდა მოთხოვნის სათაურები და დიაგნოსტიკა; ამ ცვლილების შემდეგ ავტორიზებული ამინდის მოთხოვნა ამ სესიაში ხელახლა არ შემოწმებულა.
2. Groq-ს აქვს სერვისის საკუთარი კვოტა. ლიმიტის ან შეფერხებისას საიტი აჩვენებს შეცდომას და ინარჩუნებს მონახაზს.
3. AI რეკომენდაციები და ბიუჯეტის კატეგორიები საორიენტაციოა. საიტი არ ამოწმებს სასტუმროს ფასებს, ხელმისაწვდომობას და გზის რეალურ მდგომარეობას.
4. ამ ვერსიაში არ სრულდება ჯავშნები, მოწვევების გაგზავნა ან მოწვეული ჯგუფის წევრების მართვა.
5. Supabase-ის custom SMTP არ არის გამართული ფართო მომხმარებელთა წრისთვის. მომხმარებელმა რეალური რეგისტრაცია გაიარა და არსებულ ანგარიშში შესვლა დადასტურდა, თუმცა ახალი მომხმარებლების წერილები და პაროლის აღდგენის წერილის სრული ციკლი ცალკე შესამოწმებელია.

## ლოკალური გაშვება

პროექტის საქაღალდეში, Node.js 24.15.0+ გარემოში:

```powershell
npm.cmd ci
npm.cmd run dev
```

გამოიყენე ტერმინალში ნაჩვენები მისამართი. `.env.example` აღწერს საჭირო საჯარო Supabase და სერვერულ Groq პარამეტრებს. სერვერულ გასაღებს `VITE_` პრეფიქსი არ უნდა ჰქონდეს.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`preview` იყენებს აწყობილ Worker-ს. ლოკალური მონაცემები ცალკე SQLite ბაზაში ინახება; საჯარო საიტის მონაცემები D1-შია.

## წარდგენის მოკლე სცენარი

გახსენით [დაგეგმვის განყოფილება](https://holliday-planner.dynamicabode1.chatgpt.site/#planner) და შედით უკვე შექმნილ ანგარიშში. აჩვენეთ მიმართულება, თარიღები, ადამიანების რაოდენობა და ბიუჯეტის ერთეულის ცვლილება. შექმენით AI გეგმა, მიუთითეთ ხელმისაწვდომი/მიუწვდომელი ამინდის სტატუსი, გახსენით „ჩემი გეგმები“ და ჩამოტვირთეთ საკუთარი გეგმა.

მომზადებული პრეზენტაცია შეიცავს მიზანს, მომხმარებლის გზას, ფორმას, ბიუჯეტის მაგალითს, არქიტექტურას, რეალურ AI პასუხს, შემოწმებას და დემონსტრაციის ნაბიჯებს. [სლაიდების თანმხლები ტექსტი](../deliverables/presentation-notes.ka.md) განკუთვნილია მოსამზადებლად.
